# MiniMiz — دليل التشغيل

آخر إصلاحات الخدمة:
- Worker يستخدم موديل Groq الحالي `openai/gpt-oss-120b` بدل موديل Llama المتوقف، وGemini يستخدم `gemini-3.8-flash`.
- رسالة فشل الاختصار بقت تفرّق بين إعداد ناقص، تعطل خدمة تسجيل الدخول، ومشكلة مزود الذكاء الاصطناعي.
- عرض نصوص البرومبتات وردود الـAI آمن من تفسيرها كـHTML.
- مفاتيح Gemini بتتبعت في ترويسة الطلب، ومش بتظهر في الرابط.
- تحديث أمان RLS: دالة الأدمن بتتحقق من حساب المستخدم الحالي فقط.
- الاستهلاك المجاني بقى له سقف على السيرفر؛ المؤشر للمستخدم من غير أرقام توكنز، والإدارة تشوف الاستهلاك الفعلي.
- مفيش أسعار ثابتة أو تحصيل دفع داخل التطبيق؛ طلبات الاشتراك بتتراجع يدويًا والدفع بيتفق عليه خارج التطبيق. لوحة الأدمن تعرض إشارة من الاستخدام لمراجعة توقيت تجربة الدخل.
- طلبات الاشتراك اليدوي بقت متاحة: المستخدم يطلب التفعيل ويتواصل مع الأدمن، والأدمن يراجع الدفع خارج التطبيق ثم يفعّل 30 أو 90 أو 365 يومًا من لوحة التحكم. مفيش أسعار أو تحصيل دفع داخل التطبيق.

## MiniMiz و OptiMiz
- من الشريط اللي تحت: **MiniMiz** يقلّل الكلام مع الحفاظ على لغة البرومبت ومعناه، و**OptiMiz** يحوّل الطلب لبرومبت إنجليزي مهني ومنظم؛ ممكن يطول عشان يوضح المطلوب.
- في الوضعين، اختار نوع المهمة من فوق: وكيل ذكي، ترتيب كود، تلخيص، أو تحليل. الأنواع دي بتحدد تركيز البرومبت، مش وضع الاختصار أو التحسين.
- اختيار خفيف أو متوازن أو مكثّف بيحدد درجة التغيير. في الاختصار، لو مفيش صياغة أقصر آمنة، التطبيق بيرجع النص الأصلي.
- كل نتيجة في «محفوظاتي» عليها تصنيف واضح «اختصار» أو «تحسين». بعد تحديث النسخة، شغّل ملف `schema.sql` كاملًا من SQL Editor في Supabase. الترحيل بيحافظ على نصوص المحفوظات، وبيستعيد التحسينات القديمة من نوعها أو من تمدد النتيجة أو تحويل العربي لإنجليزي؛ السجلات اللي مفيش فيها علامة واضحة بتفضل مصنفة كاختصار.
- تقدير الرموز مبني على طول النص، مش عدّاد مطابق لكل موديل أو tokenizer.

## اللي اتضاف في النسخة دي
- **حسابات حقيقية**: كل مستخدم لازم يسجّل دخول بجوجل عشان يستخدم التطبيق.
- **تسجيل دخول بجوجل** عبر Supabase Auth.
- **لوحة أدمن مخفية**: اضغط على شعار `MiniMiz` في شاشة تسجيل الدخول **دبل كليك (double-click)** فيظهر رابط صغير "دخول الأدمن". الدخول نفسه هو نفس زرار جوجل — لكن التطبيق بيتعرف إنك أدمن تلقائيًا لأن قاعدة البيانات بتربط صلاحية الأدمن بإيميلك (`abdelrahmanalaaegy@gmail.com`) مش بأي زرار. يعني حتى لو حد لقى الزرار المخفي، مش هيقدر يدخل كأدمن إلا لو سجل بنفس الإيميل ده.
- **تحليلات سلوك المستخدمين** (زيارات، أكثر الصفحات استخدامًا، عدد المستخدمين الجدد، عدد عمليات التحسين) — تظهر في تبويب الأدمن فقط.
- **مؤشر استخدام مجاني** للمستخدم، من غير كشف عدّاد التوكنز؛ والأدمن يشوف الاستهلاك والحدود حسب الحساب واليوم والأسبوع والشهر.
- **حد يومي عام وحد لكل حساب** بيتطبقوا على الخادم قبل الاتصال بمزود الذكاء الاصطناعي. الحدود الابتدائية في قاعدة البيانات 100,000 للتطبيق و20,000 لكل حساب؛ دي إعدادات بداية قابلة للتعديل من لوحة الأدمن، ولازم تضبطها على الحصة الفعلية المتاحة في حساب Groq أو Gemini.
- **توصيات المنتج والتسويق وتوقيت اختبار الدخل** تظهر داخل تبويب الأدمن حسب المستخدمين النشطين واللي بيرجعوا واستهلاك الخدمة. دي إشارات للمراجعة، مش قرار تلقائي ولا تحديد أسعار.
- الـ Worker بقى يرفض أي طلب مش مرفق بيه توكن دخول Supabase صحيح (يمنع استخدام الـ API من غير حساب).
- **واجهة بالعربية والإنجليزية**: استخدم زر اللغة في شاشة الدخول أو الشريط العلوي؛ اختيارك بيتحفظ على جهازك.

## الترتيب المطلوب منك

### 1) قاعدة البيانات (Supabase)
1. افتح مشروعك في supabase.com → **SQL Editor**.
2. الصق محتوى ملف `schema.sql` كامل ونفّذه (Run). الملف آمن يتنفذ أكتر من مرة، وبيجهز كمان جداول طلبات الاشتراك وصلاحيات التفعيل.
3. لو قاعدة البيانات شغّالة بالفعل ومش عايز تعيد تشغيل الملف كاملًا، نفّذ `subscription_workflow.sql` مرة واحدة بدلًا منه؛ هو بيضيف الجداول الجديدة من غير ما يمسح المحفوظات أو بيانات الحسابات.
4. لو حابب تغيّر إيميل الأدمن مستقبلًا، غيّره في مكانين جوه `schema.sql`: داخل `handle_new_user()` وفي جملة الـ backfill في آخر الملف، وأعد تنفيذ الملف.

### طريقة الاشتراك اليدوي
1. المستخدم يضغط **اطلب الاشتراك** من صفحة MiniMiz، ويقدر يكتب ملاحظة ثم يراسل الأدمن من زر الإيميل.
2. يظهر الطلب في **الأدمن → طلبات الاشتراك** مع إيميل المستخدم وملاحظته. اتفقوا على الدفع خارج التطبيق وتأكد من وصوله بنفسك.
3. بعد التأكيد، اختار مدة 30 أو 90 أو 365 يوم واضغط **فعّل**. التفعيل بيتم في قاعدة البيانات، والـ Worker بيتحقق منه قبل تشغيل أنواع المهام المدفوعة. لو مش هتفعّل الطلب، اضغط **رفض**.
4. المستخدم يحدّث الصفحة عشان تظهر له صلاحية الأنواع المدفوعة. الأدمن يقدر يراسله مباشرة من الإيميل الظاهر في الطلب.

### 2) تفعيل تسجيل الدخول بجوجل
**أ. Google Cloud Console** (console.cloud.google.com):
1. أنشئ مشروع (أو استخدم موجود) → **APIs & Services → OAuth consent screen** → اضبطه كـ External واملأ البيانات الأساسية.
2. **Credentials → Create Credentials → OAuth client ID** → النوع **Web application**.
3. في **Authorized redirect URIs** ضيف:
   `https://YOUR-PROJECT-REF.supabase.co/auth/v1/callback`
   (تلاقي الرابط ده جاهز في Supabase Dashboard → Authentication → Providers → Google).
4. سجّل **Client ID** و **Client Secret**.

**ب. Supabase Dashboard:**
1. **Authentication → Providers → Google** → فعّله والصق الـ Client ID/Secret.
2. **Authentication → URL Configuration** → خلي Site URL هو `https://minimum-ai.pages.dev/`، وضيف نفس العنوان ضمن Redirect URLs. أضف `http://localhost/**` فقط لو هتجرب محليًا.

### 3) اضبط إعدادات الواجهة الأمامية
افتح `index.html` ودوّر على `CONFIG` في أول السكريبت (تحت `<!-- BOTTOM NAV -->`) واملأ:
```js
const CONFIG = {
  SUPABASE_URL: 'https://YOUR-PROJECT-REF.supabase.co',
  SUPABASE_ANON_KEY: 'YOUR-SUPABASE-ANON-KEY',      // Project Settings → API → anon public
  WORKER_URL: 'https://minimum-api.YOUR-SUBDOMAIN.workers.dev/api/optimize',
  ADMIN_EMAIL: 'abdelrahmanalaaegy@gmail.com',
};
```
مفتاح `anon` آمن إنه يكون في الواجهة — الحماية الحقيقية موجودة في RLS جوه `schema.sql`.

### 4) إعداد ونشر الـ Worker (Cloudflare)
1. في ملف `wrangler.toml`، خلي `SUPABASE_URL` هو نفس رابط مشروع Supabase الموجود في `index.html`.
2. من مجلد المشروع، نفّذ الأوامر دي. استخدم نفس مفتاح anon العام الخاص بالمشروع نفسه:
```bash
npx wrangler login
npx wrangler secret put GROQ_API_KEY
npx wrangler secret put SUPABASE_ANON_KEY
npx wrangler secret put SUPABASE_SECRET_KEY
npx wrangler deploy
```
قيمة `SUPABASE_SECRET_KEY` تتاخد من Supabase → **Project Settings → API Keys → Secret key**. ينفع استخدام مفتاح `service_role` القديم مؤقتًا بنفس اسم السر. المفتاح ده بيدي الخادم صلاحيات عالية: خليه Secret داخل Cloudflare Worker فقط، وما تحطوش في `index.html` أو GitHub أو `wrangler.toml`. الـWorker بيستخدمه لتسجيل الاستهلاك وحجز السقف ذريًا؛ مفتاح `anon`/`publishable` يفضل للواجهة والتحقق من جلسة المستخدم.
لـCloudflare Preview deployments، ضيف نفس سر قاعدة البيانات التجريبية فقط، واستخدم Supabase staging منفصل. ما توصلش Preview بقاعدة الإنتاج.
لو كنت ضايف `SUPABASE_URL` كـ Secret في Cloudflare، امسحه قبل النشر؛ الرابط بيتحدد كـ Variable في `wrangler.toml`.
هتاخد رابط زي `https://minimum-api.<subdomain>.workers.dev` — ده اللي تحطه في `WORKER_URL` فوق.
لو عايز تستخدم Gemini بدل Groq، غيّر `AI_PROVIDER = "gemini"` في `wrangler.toml` وضيف السر بالأمر `npx wrangler secret put GEMINI_API_KEY`. النموذج المستخدم هو `gemini-3.8-flash`.

### بعد أي تعديل على الـWorker
- أمر `npx wrangler preview` للمعاينة فقط، ومش بينشر الخدمة الأساسية.
- أمر `npx wrangler deploy` هو اللي ينشر الـWorker على رابط الإنتاج.
- لو Cloudflare بيبني من GitHub، تأكد إن أمر النشر الأساسي هو `npx wrangler deploy`، وأسرار `GROQ_API_KEY` و`SUPABASE_ANON_KEY` و`SUPABASE_SECRET_KEY` متسجلة من إعدادات Worker Secrets. ما تحطش الأسرار في GitHub أو ملفات المشروع.

## اختبار سريع
1. افتح الموقع → هتلاقي شاشة تسجيل دخول → اضغط "تسجيل الدخول بجوجل".
2. جرّب تحسين برومبت — هيتحفظ تلقائيًا في `prompts_history` مرتبط بحسابك.
3. لتجربة الأدمن: من نفس شاشة الدخول (لو خرجت)، دوس على الشعار دبل كليك (double-click) → هيظهر "دخول الأدمن" → ادخل بإيميل `abdelrahmanalaaegy@gmail.com` → هيظهر تبويب **Admin** تحت لوحدك.
4. بعد تشغيل `schema.sql` وإضافة سر الـWorker، جرّب طلبًا ثم افتح الأدمن: هتلاقي عدّاد التوكنز الحقيقي وحدود الاستخدام ومؤشرات التفاعل. المستخدم العادي يشوف شريطًا فقط.
5. من الأدمن عدّل سقف التطبيق والحساب بما يناسب حصة مزود الذكاء الاصطناعي. خلي سقف الحساب أقل من سقف التطبيق. إعدادات الجاهزية الافتراضية (50 مستخدمًا نشطًا خلال 30 يومًا، و25% عودة، و20 مستخدمًا نشطًا خلال 7 أيام) قابلة للتعديل، وما بتفعّلش الدفع تلقائيًا.

## ملاحظات أمان
- أي شخص تاني هيسجل دخول بجوجل هيبقى مستخدم عادي بس (`is_admin = false`) — مفيش طريقة يوصل بيها للوحة الأدمن غير إنه يملك نفس إيميل الأدمن المسجل في قاعدة البيانات.
- الـ Worker دلوقتي بيتأكد من صحة توكن Supabase قبل ما يكلم Groq/Gemini، فمحدش هيقدر يستهلك رصيدك من غير تسجيل دخول.
- مفتاح Supabase السري موجود على الخادم فقط. كل طلب يحجز جزءًا من السقف قبل استدعاء الذكاء الاصطناعي، ثم يُسوّى على أرقام المزود الفعلية؛ الطلب الفاشل اللي ما نعرفش استهلاكه يفضل محجوزًا بشكل محافظ لحماية الرصيد.
